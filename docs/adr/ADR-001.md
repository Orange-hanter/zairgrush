
# ADR-001: журнал петли — jsonl-первичный (E1 закрыт)

## Контекст

E1 (06-док, §4) сравнивал два варианта журнала петли: A — md-первичный
(`.swarm/log/NNN-*.md`, схема v0.6 дизайн-дока), B — jsonl-первичный
(типизированные события, md — рендер по запросу).

## Решение

Журнал петли — **jsonl-первичный**: `.swarm/log/run.jsonl` с
типизированными событиями (handoff, verdict, gate_result, commit,
escalation); md-представления генерируются командой (`swarm report`).
В 05-док внести при следующей версии (правка §3-диаграммы и §8).

## Альтернативы

За три прогона (SMOKE-1, BENCH-1, CANARY-1) раннеры писали только jsonl
(`metrics.jsonl` bench/canary + `findings.jsonl`): 31 + 19 строк метрик,
23 наблюдения. Весь пост-анализ (агрегация стоимости, сверка ожиданий
канареек, таблицы отчётов) выполнен запросами к jsonl за секунды.
Md-журнал итераций не понадобился ни разу; человекочитаемые отчёты
(`smoke1/report.md`, `bench/report.md`, `canary/report.md`,
`07-experiments-journal.md`) написаны ИЗ jsonl — то есть «md как рендер»
уже фактическая практика, а не гипотеза. Вариант A не реализовывался за
ненадобностью: ни одна задача пост-анализа не потребовала md-первичного
источника.

## Последствия

- (+) Пост-анализ и replay-тесты FSM получают машиночитаемые фикстуры
  бесплатно; документатор (§3.3) читает первичные данные напрямую.
- (+) Нет двойной записи и дрейфа между md и данными.
- (−) Человек не читает сырой журнал без рендера — компенсируется
  `swarm report` и отчётами документатора.
- Правило программы: эксперимент E1 закрыт без прогона варианта A —
  зафиксировано как «решение по факту практики» (3 прогона, 0 случаев
  нужды в A); при появлении задачи, требующей md-первичности, ADR
  пересматривается.
