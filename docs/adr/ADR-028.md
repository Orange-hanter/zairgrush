
# ADR-028: Документный дифф: skip ADR-027 ограничивается порогом doc_skip_max_lines (выкл. по умолчанию)

| Поле | Значение |
|------|----------|
| **Статус** | ✅ accepted |
| **Дата** | 2026-09-26 |
| **Автор** | dakh |

## Контекст

Дополняет ADR-027, п.1. ADR-027 ввёл маршрут skip для docs_only-диффа (все пути .md/.rst/.adoc) из довода «прозу дорогой моделью не ревьюим» — и сделал это БЕЗ ограничения по размеру: BAND_MAX_LINES (100) действует только на кодовую бэнду. Полевой аудит сессии ZeusLogic 2026-09-20 (15-field-audit-zeuslogic.md §1, задача AUD-001) показал обратную сторону: на проекте, где документ — источник истины и правится ДО кода, документный дифф — контракт (docs/09 §5.1 задал сигнатуры, по которым писался код). Больше половины выпущенного объёма сессии — документы (docs/07 216 строк, docs/09 168, docs/10 245, docs/11 236), и ни один не прочитан ревьюером: обе строки вердикта по d7ga — cost_usd 0.0. docs_check проекта ловит форму (frontmatter, журнал, ссылки), не смысл. Чем ближе изменение к источнику истины, тем меньше проверки оно получало.

## Решение

1. Новый ключ swarm.toml `doc_skip_max_lines` (целое ≥ 0). docs_only-дифф с diff_lines > порога уходит на ПОЛНОЕ ревью с событием журнала guard_block reason=doc_size; ≤ порога — прежний skip ADR-027. 2. Умолчание — ключа нет, поведение ADR-027 не меняется: порог не мерен, включать его — решение стенда (проект, где документы — контракт), а не петли. 3. Мусорное значение (не int, bool, отрицательное) ошибается в сторону полного ревью (порог 0). 4. Определение «документного диффа» остаётся прежним: `is_doc` по ВСЕМ путям диффа, суффиксы .md/.rst/.adoc; .txt не документ (урок g1nt). 5. triage = false (стенд-измеритель) по-прежнему отключает бэнду целиком, порог не читается. Реализация: triage.doc_over_limit, triage.decide; тесты test_triage.TestDocSizeLimit и TestSkipRoute.test_doc_over_limit_calls_the_reviewer; две мутации в mutate.py.

## Альтернативы

(i) Дешёвая рука triage_arm на документный дифф вместо skip (~$0.1–0.3 за дифф) — отвергнуто: REV-001 показал 0/3 endorsed majors у дешёвой руки на коде, на прозе её ценность не мерена; включать вслепую — подгонка. (iii) Отдельная роль «сверить спецификацию с кодом, который она описывает» — отвергнуто сейчас: новая дорогая роль без замера; остаётся кандидатом. (iv) Оставить skip и записать «документы проверяет человек» — отвергнуто: закрепляет обратный градиент проверки на проектах, где документ — контракт. Порог ВКЛЮЧЁННЫЙ по умолчанию (например, 40) — отвергнуто: значение не мерено, менять поведение всех стендов догадкой нельзя. Замер стоимости ревью на четырёх документах сессии 2026-09-20 не проводился: с 2026-09-26 владелец остановил эксперименты (только доводка и функционал); цена полного ревью крупного документного диффа оценивается по порядку медианы кодового ревью пилота (~$1–3), это оценка, не замер.

## Последствия

+ Стенд, где документ — контракт, может вернуть ревью крупным спецификациям одной строкой конфига; причина смены маршрута видна в журнале (guard_block doc_size), экономия и её отмена меряются по тем же событиям band_hit/guard_block. + Поведение существующих стендов не меняется. − Значение порога на стенде — выбор без калибровки; при включении на ZeusLogic все четыре документа сессии 2026-09-20 (168–245 строк) ушли бы на полное ревью при любом пороге < 168. − Отложен замер (что ревью находит в документах и сколько стоит) — открытый вопрос для будущей программы экспериментов, не решён здесь. − ADR-027 п.1 читается вместе с этим ADR: skip docs_only теперь условен при заданном ключе.
