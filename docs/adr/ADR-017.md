
# ADR-017: хелперы работают через нативный Ollama /api/chat; thinking задаётся явно

| Поле | Значение |
|------|----------|
| **Статус** | ✅ accepted |
| **Дата** | 2026-08-07 |
| **Автор** | cursor-grok |

## Контекст

Хелперы третьего контура должны быть дёшевыми, быстрыми и воспроизводимыми. Их текст идёт в промпт дорогих ролей, поэтому непригодный ответ (пустой content, обрезок, мусор) дороже отсутствия.

ADR-003 запретил reasoning-модели: на коротком лимите они сжигали бюджет в размышления и возвращали пусто. Замер шёл через OpenAI-совместимый `/v1`. У этого слоя нет параметра `think`, и он молча игнорируется. Вывод «модель непригодна» оказался ошибкой атрибуции: непригодна была комбинация «reasoning-модель + транспорт без управления thinking».

OLLAMA-1 показал нативный `/api/chat` по тому же Bearer-ключу, с явным `think` и с `options` (`num_predict`, `seed`, `temperature`). `format` со схемой на облаке игнорируется — структура ответа хелпера остаётся нашей проверкой.

Запись ADR-004 это уже приняла (2026-08-07, заменила ADR-003), но в «Альтернативах» лежал разбор OLLAMA-1, а уточнения REVIEWARM утонули в последствиях вместе с открытым вопросом владельца. Решение не меняется; меняется запись.

## Решение

Хелперы вызывают `https://ollama.com/api/chat`, не `/v1`.

- В каждом запросе `think` передаётся явно. Умолчание вызова — `false`. На дефолты модели полагаться нельзя: они включают рассуждения.
- Требование ADR-003 «только non-reasoning» снято: пригодна любая модель, у которой thinking управляем. Семейства, где трассу нельзя выключить (только понижение до `low`), для хелперов не берём, пока владелец не снимет это ограничение отдельно.
- Умолчание модели — `gemma4:31b` (скорость и качество, не отсутствие reasoning).
- `options`: `temperature: 0`, `top_k: 1`, `repeat_penalty: 1.0`, явный `num_predict`, `seed`. `num_ctx` / `truncate` / `shift` не передаются.
- Текст хелпера всегда проходит механическую проверку: `format` со схемой на облаке игнорируется.

Не выбрано: `/v1` и запрет reasoning-моделей как свойство модели.

## Альтернативы

**A. Оставить OpenAI-совместимый `/v1` и запретить reasoning-модели (ADR-003).**
Отвергнут: `/v1` молча игнорирует `think`. Пустой ответ при коротком лимите — свойство транспорта, не модели. Запрет отсекает весь каталог, где thinking управляем.

**B. Нативный `/api/chat`, но полагаться на дефолты модели.**
Отвергнут: если модель умеет thinking и `think` не передан, сервер включает рассуждения сам. Обе thinking-capable модели при `think: true` и коротком лимите возвращают пустой content.

**C. Нативный `/api/chat` с явным `think` в каждом запросе.**
Принят. С `think: false` та же «непригодная» модель отвечает за 0.8 с и 15 токенов вместо 4.9 с и 679. Structured outputs на облаке нет — это не альтернатива, а ограничение вендора.

## Последствия

**Плюсы**
- Каталог облачных моделей открыт по качеству и скорости, а не по ярлыку non-reasoning.
- Детерминизм настоящий: на `/v1` нам молча навязывали `temperature=1.0`. Есть `done_reason == "length"` и `x-request-id`.
- Текст хелпера по-прежнему проходит механическую проверку; без `format` это единственная защита контракта.

**Минусы**
- Нативный API не отраслевой стандарт: смена провайдера = переписать ~40 строк клиента.
- Правило «не платим за размышления» верно для metered-контуров и бессмысленно на плоской подписке Ollama Cloud; потолок `num_predict` с чужого контура давал ложные вердикты «модель непригодна».

**Что осталось**
- Уточнение 2026-08-20: `think` — свойство модели, не константа вызова; метрика обязана нести `thinking_chars`, иначе обрыв по размышлениям читается как «модель плоха». В `helpers.ollama_chat` `think` всё ещё зашит `False`.
- Запрет семейств вроде `gpt-oss:*` опровергнут в посылке (при достаточном потолке модель отвечает). Снимать ли его для состава хелперов — решение владельца, этим ADR не принимается.
- Пересмотр умолчания `gemma4:31b` — отдельная очередь, не этот ADR.
