
# ADR-010: роутинг моделей в сворме по квоте — k3-256k вместо k3-1M, пул субагентов без force

| Поле | Значение |
|------|----------|
| **Статус** | 🔁 superseded |
| **Дата** | 2026-08-22 |
| **Автор** | sym007-import |

## Контекст

План Allegro упёрся в квоту: недельная квота и скользящее 5-часовое окно
выглядят «маленькими» для сворм-задач. Разбор локальных wire-файлов
(`~/.kimi-code/usage-report.py`, 14 дней, 08–22 августа) дал картину:

- всего **~555M токенов** (in 13.3M + out 3.0M + cache-read 539M), 5231 запрос;
- **средний контекст запроса ~105k токенов** — помещается в 256k-окно;
- **основной агент — 76% расхода** (9.7M in / 411M cache-read), субагенты — 24–26%;
- 97% объёма — cache-read: цена задачи определяется перечитыванием контекста,
  а не генерацией;
- пиковый день 21.08 — ~118M токенов (сворм-сессии ZAIrgRush).

Конфиг на момент замера: main = `kimi-code/k3` (1M) при
`[thinking].effort = "high"`, `[secondary_model] force = true` прибивает всех
субагентов к `kimi-for-coding-highspeed` (K2.7, 256k), алиас `k3-256k`
определён. Экспериментальный пул субагентов активен
(`KIMI_CODE_EXPERIMENTAL_SECONDARY_MODEL=1` в env — проверено).

Из официальной документации: **`k3` (1M) расходует примерно вдвое больше
квоты, чем `k3-256k`**, при идентичных результатах в пределах 256k контекста.
Глобальный `[thinking].effort`, если задан, перекрывает `default_effort`
моделей **для главного агента и субагентов одинаково**.

## Решение

1. **Дефолт главного агента — `k3-256k`.** Средний контекст 105k << 256k,
   официальная паритетность качества в пределах 256k, экономия квоты ~2×
   на доминирующих 76% расхода. `k3` (1M) — только явным выбором на задачах,
   где контекст реально >200k (анализ больших деревьев, длинные документы).
   Ожидаемый эффект больше любой оптимизации субагентов: они всего четверть
   расхода.
2. **Пул субагентов вместо `force`:** убрать `force = true`, дефолт пула —
   `kimi-code/kimi-for-coding` (обычный, не highspeed: highspeed — это про
   латентность, по подсказке в доке он «priced higher»), в пул добавить
   `kimi-code/k3-256k` для сложных субагентов. Выбор — за главным агентом
   per spawn (параметр `model` в `Agent`/`AgentSwarm`). Подтверждает гипотезу
   заявки: для субагентов k3-256k — правильный «дешёвый K3», но большинству
   механических субзадач хватает K2.7 (см. ADR-002: исходы идентичны на
   тривиальном классе).
3. **Убрать глобальный `[thinking].effort = "high"`.** Пока он задан, он
   выигрывает у `default_effort` всех моделей, включая субагентов. Без него
   главный останется на high (дефолт алиаса k3-256k), а для пула можно
   зарегистрировать low-effort вариант (`[models.k3-256k-low]` с
   `overrides.default_effort = "low"`) и отдавать на него рутинные субзадачи.
4. **Кэш-гигиена** (97% объёма — cache-read): сессии продолжать сразу, не
   давая кэшу протухнуть в idle; длинные сессии компактить, а не
   перезапускать с нуля (полный re-read дороже компакшена);
   `cache_expiry_hint` в tui.toml оставить включённой.
   `thinking.keep = "off"` уже стоит — сохранить.
5. **Дисциплина сворма** (без изменения конфига): узкие промпты субагентам
   (каждый тащит свой контекст), батчить независимые разведки в одну,
   ограничивать fan-out; `max_attempts_per_step = 5` уже снижен — сохранить.

## Последствия

- (+) Ожидаемое снижение расхода квоты ~2× на главном агенте при том же
  качестве в пределах 256k — по официальному заявлению провайдера.
- (+) Пул субагентов возвращает главному агенту выбор модели per spawn
  вместо глухого force; low-effort вариант удешевляет рутину.
- (−) На `k3-256k` с `reserved_context_size = 80000` автокомпакшен
  срабатывает при ~176k контекста: задачи в диапазоне 176k–1M будут
  компактиться раньше, чем на 1M-модели, либо потребуют явного возврата
  на `k3`. Это и есть критерий переключения.
- (−) Снятие глобального effort полагается на `default_effort` алиасов;
  при добавлении новых моделей в `[models]` поле надо копировать явно.
- **Проверка обязательна:** через 1–2 недели повторить `usage-report.py` и
  сверить `/usage`; качество — по числу итераций ревьюера на ближайшем
  бенче (процедура ADR-002). Если регрессия видна — вернуть дефолт на `k3`,
  оставив п.2–5: они независимы.
- Открытый вопрос: точная цена `kimi-for-coding-highspeed` относительно
  обычного `kimi-for-coding` в квоте официально не опубликована; дефолт пула
  выбран консервативно (обычный), пересмотреть при появлении данных.
