
# ADR-022: дефолт kimi — k3-256k; пул субагентов без force

| Поле | Значение |
|------|----------|
| **Статус** | ✅ accepted |
| **Дата** | 2026-08-22 |
| **Автор** | cursor-grok |

## Контекст

План Allegro упёрся в квоту Kimi. Разбор wire-файлов за 14 дней (~555M токенов, 5231 запрос): средний контекст ~105k, 97 % объёма — cache-read, главный агент — 76 % расхода, субагенты — четверть. Пик — сворм-сессии ZAIrgRush.

Конфиг на замере: main = `kimi-code/k3` (1M), глобальный `[thinking].effort = "high"` бьёт и главного, и субагентов, `force = true` прибивает всех субагентов к highspeed K2.7. По документации провайдера `k3` (1M) в пределах 256k ест примерно вдвое больше квоты, чем `k3-256k`, при том же качестве.

Запись ADR-010 это уже приняла (2026-08-22), но alternatives были пусты, а решение читалось как чеклист конфига. Решение не меняется; меняется запись.

## Решение

Дефолт главного агента — `k3-256k`. `k3` (1M) — только явным выбором, когда контекст реально >200k.

Пул субагентов вместо `force`: `force = true` снимается. Дефолт пула — `kimi-code/kimi-for-coding` (не highspeed). В пул добавляется `kimi-code/k3-256k` для сложных субзадач. Выбор — за главным агентом per spawn.

Глобальный `[thinking].effort = "high"` снимается: он перекрывал `default_effort` всех моделей. Главный остаётся на high дефолтом алиаса; для рутины пула — отдельный low-effort алиас.

Кэш: сессии продолжать сразу; длинные — компактить, не перезапускать с нуля; `cache_expiry_hint` и `thinking.keep = off` сохранить. Промпты субагентам узкие, fan-out ограничен.

Не выбрано: дефолт 1M; глухой force всех субагентов на highspeed.

## Альтернативы

**A. Оставить дефолт главного агента `k3` (1M).**
Отвергнут: средний контекст запроса ~105k, в 256k помещается. По документации провайдера `k3` в пределах 256k расходует ~2× квоты относительно `k3-256k` при том же качестве. Главный агент — 76 % расхода; это больше любой оптимизации субагентов.

**B. Оставить `force = true` и прибить субагентов к `kimi-for-coding-highspeed`.**
Отвергнут: главный теряет выбор per spawn. highspeed — про латентность и «priced higher». Большинству механических субзадач хватает обычного K2.7 (ADR-002: исходы идентичны на тривиальном классе).

**C. `k3-256k` как дефолт, пул без force, без глобального `thinking.effort = high`.**
Принят. `k3` (1M) — явным выбором, когда контекст реально >200k.

## Последствия

**Плюсы**
- Ожидаемое ~2× снижение квоты на главном агенте при том же качестве в пределах 256k.
- Пул возвращает выбор модели per spawn; low-effort — на рутину.

**Минусы**
- На `k3-256k` с `reserved_context_size = 80000` автокомпакшен раньше (~176k). Задачи 176k–1M либо компактятся, либо явно возвращаются на `k3` — это критерий переключения, не сюрприз.
- Снятие глобального effort полагается на `default_effort` алиасов; новые модели в `[models]` должны копировать поле явно.

**Что осталось**
- Повторить `usage-report.py` и сверку `/usage`; качество — число итераций ревьюера по процедуре ADR-002. Регрессия → вернуть дефолт на `k3`, пункты про пул и кэш оставить.
- Цена `kimi-for-coding-highspeed` vs обычного в квоте официально не опубликована; дефолт пула консервативный.
