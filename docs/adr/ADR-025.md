
# ADR-025: Каноническое хранение ADR: таблица adr в cod-doc DB

| Поле | Значение |
|------|----------|
| **Статус** | ✅ accepted |
| **Дата** | 2026-09-12 |
| **Автор** | dakh |

## Контекст

ADR жили в трёх местах: прозаические оригиналы experiments/adr/NNN-name.md, проекции docs/adr/ADR-NNN.md и таблица adr в cod-doc DB. Проекции docs/adr дополнительно импортировались как Documents (module-spec), что создавало дублирование: одна сущность — две строки в DB (adr + documents) и риск рассинхрона.

## Решение

Канонический источник ADR — таблица adr в cod-doc DB (cod-doc adr list/graph). docs/adr/ADR-NNN.md — генерируемые проекции (cod-doc adr export), руками не править и НЕ импортировать как Documents: cod-doc import docs запускать с --exclude 'docs/adr'. experiments/adr/*.md — исторические прозаические оригиналы, остаются Documents и не редактируются. Новые ADR создаются только через cod-doc adr new.

## Альтернативы

1) Каноникал — файлы docs/adr, DB как индекс: отклонено, теряется граф связей и статусы в DB. 2) Каноникал — experiments/adr: отклонено, это исторические прозаические тексты без нормализованных полей. 3) Держать дубль Documents+adr с ручной синхронизацией: отклонено, источник рассинхрона.

## Последствия

+ Одна строка на решение в DB; drift-контроль не дублируется; arch/README уже описывает эту модель. − Флаг --exclude 'docs/adr' при импорте — конвенция, не enforced конфигом; 24 строки documents удаляются из DB (файлы на диске остаются).
