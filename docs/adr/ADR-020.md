
# ADR-020: гибридная навигация по коду — пакетный индекс, LSP, ctags

| Поле | Значение |
|------|----------|
| **Статус** | ✅ accepted |
| **Дата** | 2026-08-08 |
| **Автор** | cursor-grok |

## Контекст

ADR-006 закрепил карту в handoff, но не ответил, чем её строить. ADR-007 отверг ctags — по Exuberant Ctags 5.8 (2009): `brew install ctags` ставит его, а нужен конфликтующий `universal-ctags`. Параллельно у Claude Code есть родной LSP (pyright, rust-analyzer) уже в настройках машины.

Пакетный индекс, сессионный LSP и широкий ctags решают разные задачи. Склеивать их в «один инструмент» значит либо врать точностью, либо терять языки. Агенту нельзя выдавать совпадение по имени как разрешённый вызов: на приблизительной ссылке ревьюер построит finding, исполнитель — правку.

Запись ADR-008 это уже приняла (2026-08-08, заменила ADR-007), но «Альтернативы» были таблицей возможностей, а отказы (мёртвые MCP, grep-навигаторы) жили в последствиях. Решение не меняется; меняется запись.

## Решение

Три инструмента, три непересекающиеся роли.

1. Пакетный артефакт в handoff (карта и blast radius): `ast` для Python, `rust-analyzer --scip` или tree-sitter для Rust. Контекст готов до старта сессии.
2. Точечные доуточнения по ходу работы — родной LSP. Бесплатен, требует языковой сервер и корректный корень проекта.
3. Широкий охват языков — universal-ctags: определения и импорты там, где нет нашего разрешателя.

Гибридный индекс склеивает (1) и (3) и помечает достоверность каждой связи: `resolved`, `import`, `name-match`. В выводе — от точного к приблизительному, с подписью.

Не выбрано: один инструмент на все роли; отдельный MCP навигации.

## Альтернативы

**A. Только stdlib `ast`.**
Отвергнут: точные вызовы только для Python. Репозиторий петли уже не одноязычный, и карта без остальных языков врёт молчанием.

**B. Только universal-ctags.**
Отвергнут: даёт определения и импорты (164 языка, 14 мс на стенде), но не «кто зовёт». ADR-007 отверг ctags по Exuberant 5.8 (2009) — это была ошибка атрибуции версии, не довод против universal-ctags 6.x.

**C. Только родной LSP.**
Отвергнут: `incomingCalls` совпал с ast-индексом на `clean_token`, но LSP реактивен и сессионен. Stateless-агенту нужен пакетный артефакт в файле/промпте до старта, не ответ по позиции в открытой сессии. Отдельный MCP навигации не нужен: плагины pyright/rust-analyzer уже есть; `mcp-language-server` мёртв.

**D. Три роли: пакетный индекс в handoff, LSP по ходу, ctags как широкий слой.**
Принят. Связи в гибридном индексе помечаются уровнем достоверности (`resolved` / `import` / `name-match`), от точного к приблизительному. Догадку нельзя выдавать за факт.

## Последствия

**Плюсы**
- Мультиязычность без потери точности на Python: ctags покрывает всё, `ast` уточняет вызовы, tree-sitter добирает языки без разрешателя.
- LSP-ветка бесплатна и уже включена — это замена отдельному MCP навигации.
- Индекс кросс-проверен: LSP `incomingCalls` совпал с ast-гибридом.

**Минусы**
- Три зависимости вместо нуля. Смягчено: все опциональны; `ast` работает всегда; `have_ctags()` отвергает Exuberant по строке версии.
- LSP требует корень проекта с разрешёнными импортами, иначе `findReferences` молча возвращает только определение.

**Что осталось**
- Не брать `codanna` / `code-graph-rag` как зависимость (bus-factor 1); идеи — да.
