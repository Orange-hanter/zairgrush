
# ADR-015: журнал петли — jsonl-первичный

| Поле | Значение |
|------|----------|
| **Статус** | ✅ accepted |
| **Дата** | 2026-08-07 |
| **Автор** | cursor-grok |

## Контекст

Петля сворма собирается из коротких свежих запусков агентов: сами агенты stateless, а память о том, что уже случилось, живёт только в файлах и в git. Журнал прогона — единственная хроника фактов: какой раунд прошёл, что сказал ревьюер, красный ли гейт, состоялся ли коммит, спросили ли человека. Его читают две аудитории с несовместимыми требованиями.

Машинам нужны типизированные события: replay-тесты конечного автомата, доска, `swarm ab`, агрегация стоимости, вход для документатора. Человеку нужна связная хроника задачи, а не дамп. Агентам сырой журнал целиком скармливать нельзя — это чужой контекст и лишние токены; исполнителю в крайнем случае дают короткую выжимку «что уже пробовали».

Дизайн-док v0.6 фиксировал обратное: первичным журналом были markdown-файлы `.swarm/log/NNN-*.md` (один файл на handoff, писался «для человека и для пост-анализа»), а jsonl оставляли метрикам. На практике это значит либо парсить прозу, либо вести вторую запись рядом и ловить дрейф. Эксперимент E1 в `06-knowledge-infra-experiments.md` §4 как раз и ставил этот выбор: оставить md источником истины или инвертировать схему.

Запись ADR-001 это решение уже приняла (2026-08-07), но в шаблон COD-DOC она попала с перепутанными полями: контекст не описывал задачу, в «Альтернативах» лежали замеры прогона, в решении висел хвост «внести в 05-док». Решение не меняется; меняется запись.

## Решение

Журнал петли — jsonl-первичный. Markdown не источник истины, а рендер.

- Факты прогона пишутся append-only в `.swarm/log/run.jsonl`: одна строка — одно типизированное событие (`kind`: раунд, вердикт, гейт, коммит, эскалация, нарушение границ и остальные виды из `swarm/vocab.py`). В каждой строке — `run_id` и `swarm_sha`.
- Стоимость и время — в `.swarm/metrics.jsonl`. Диагностика (`diag.jsonl`) — отдельный поток, не журнал фактов.
- Человекочитаемый вид даёт `swarm report` (и доска) по общему словарю `swarm/vocab.py`. Фраза не имеет права терять поля: неназванное уходит в хвост `ключ=значение`; сырьё доступно через `--json`.
- Параллельный md-первичный журнал не пишем. Двойной записи нет.

Не выбрано: md как первоисточник и двойная запись (см. альтернативы).

## Альтернативы

**A. Markdown-первичный журнал** (схема дизайн-дока v0.6: `.swarm/log/NNN-*.md` как источник истины, jsonl только для метрик).
Отвергнут: пост-анализ трёх прогонов (SMOKE-1, BENCH-1, CANARY-1) всегда шёл запросами к jsonl — 31+19 строк метрик, 23 наблюдения; человекочитаемые отчёты написаны из jsonl. Ни одна задача не потребовала md как первоисточник. Парсер прозы всё равно понадобился бы, а фикстур для replay FSM markdown не даёт.

**B. Двойная запись** (md и jsonl оба «первичны»).
Отвергнут: два источника истины расходятся. Документатор, доска и тесты начинают спорить, какой файл авторитетен — ровно тот дрейф, который петля не выдерживает.

**C. jsonl-первичный журнал, markdown — рендер по запросу.**
Принят. Так петля уже работала на тех трёх прогонах; вариант A не реализовывался, потому что на него не нашлось ни одной задачи.

## Последствия

**Плюсы**
- Replay-тесты FSM, `swarm ab`, доска и агрегация стоимости получают машиночитаемые фикстуры без отдельного экспорта.
- Один источник фактов: нет дрейфа между прозой и данными.
- Документатор читает журнал как данные, а не как контракт прозы.

**Минусы**
- Человек не читает сырой jsonl. Компенсация — `swarm report` (фразы из `swarm/vocab.py`, хвост `ключ=значение` для неназванных полей) и `swarm report --json` для сырья.
- Диагностика обязана жить отдельно: трассировка в журнале фактов ломает контракт «факт либо случился, либо нет».

**Что осталось сделать**
- В `05-agent-swarm.md` схема §3 и пункт журнала в §8 всё ещё называют `.swarm/log/NNN-*.md` первичным — это хвост v0.6, его надо заменить на `run.jsonl`.
- Эксперимент E1 закрыт без контрольного прогона варианта A (3 прогона, 0 случаев нужды в md-первичности). Пересматривать этот ADR стоит только если появится реальная задача, которой jsonl как источник не хватает.
