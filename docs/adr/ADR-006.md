
# ADR-006: карта репозитория в handoff — да, но не всегда

| Поле | Значение |
|------|----------|
| **Статус** | 🔁 superseded |
| **Дата** | 2026-08-08 |
| **Автор** | sym007-import |

## Контекст

Архитектура петли делает агентов stateless (§3): каждая итерация — свежая
сессия без памяти о предыдущих. Плата за это — повторное исследование
репозитория в каждом запуске. Величина платы не измерялась ни разу.

E3 сравнивал handoff без карты (A) и с картой символов (B) на трёх
задачах, требующих знания чужого кода.

## Решение

**Карта символов включается в handoff исполнителя**, строится на stdlib
`ast` (сигнатуры + первая строка docstring, ранжирование PageRank по графу
вызовов), бюджет — порядка 25 строк и 500 токенов.

**Но не безусловно.** Карта прикладывается, когда задача требует
ориентации в чужом коде: несколько разрешённых путей, новый модуль,
интеграция существующих функций. Для локальной правки в одном файле она не
нужна и, по данным E3, может добавить лишних чтений — агент идёт смотреть
реализации, которые иначе бы не открыл.

**Blast radius** (кто вызывает изменённые функции) остаётся реализованным,
но **по умолчанию выключен — и замер это скорее подтверждает**.

Вариант C проверен на реальном проекте (tenacity) канарейками, невидимыми
для тестов. Единственное валидное сравнение дало паритет: ревьюер без
карты нашёл вызывающих (5 находок, $0.69), с картой — тоже (4 находки,
$0.68). Причина видна в его же рассуждении: он прослеживает цепочку сам —
«путь один: `BaseRetrying._run_wait` (`tenacity/__init__.py:428`) кладёт
результат wait-стратегии…» — пользуясь `Read` и `Grep`, которые у него и
так есть.

Побочный эффект оказался важнее пользы: карта удлиняет промпт, и на второй
канарейке ревью оборвалось с `error_max_budget_usd` ($1.054 при лимите
$1.00), тогда как без карты хватило $0.97. То есть включение blast radius
требует пересмотра бюджета ревью.

Замер доведён на обеих канарейках: **вызывающий замечен во всех четырёх
прогонах** (2/2 без карты, 2/2 с картой). Прироста обнаружения нет.

Но одна деталь меняет формулировку вывода: на второй канарейке вариант с
картой оказался **дешевле** ($1.02 против $1.40) при большем числе находок
(6 против 5) — готовый список вызывающих избавил ревьюера от
самостоятельного поиска. На первой разницы не было ($0.68 против $0.69).

Значит карта не бесполезна — она просто **не про обнаружение**: recall она
не поднимает, но может сокращать работу ревьюера там, где связи
неочевидны. Выборка мала (две пары), поэтому решение остаётся «выключено
по умолчанию» с возможностью включать точечно — на крупных диффах, где
цена поиска связей высока.

## Альтернативы

| Метрика | Без карты | С картой |
| --- | --- | --- |
| Обращений к репозиторию (Read/Grep/Glob) | 17 | **10** (−41 %) |
| Из них `Glob` — поиск нужных файлов | 3 | **0** |
| Суммарное время | 147 с | 147 с |
| Результат | 3/3 done | 3/3 done |

На одной из трёх задач (самой простой) эффект оказался обратным: 5 вызовов
против 4. Прямое сравнение по токенам невозможно — Kimi не отдаёт `usage`.

## Последствия

- (+) Фаза «где что лежит» исчезает: `Glob` уходит в ноль.
- (+) Реализация без зависимостей: `ast` вместо tree-sitter/ctags, около
  двухсот строк, 17 тестов.
- (+) Побочный выигрыш для других ролей: та же карта годится планировщику
  для заполнения `paths`/`deps`, а `blast_radius` — ревьюеру.
- (−) Карта конкурирует за контекст с самой задачей; бюджет строк
  обязателен, иначе воспроизводим ту проблему, ради которой затевались
  (§8).
- (−) Выигрыш измерен косвенно (число вызовов, не токены) — провайдер не
  отдаёт usage. Прямое доказательство появится, если исполнителя
  когда-нибудь переведут на API с честной телеметрией.
- Условие включения («когда задача требует ориентации») пока эвристика, а
  не измеренное правило: на одной задаче из трёх карта навредила. Уточнять
  на большем наборе.
