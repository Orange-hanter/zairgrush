
# ADR-014: cod-doc — единая поверхность планирования: документы, ADR, задачи; legacy YAML мигрирован

| Поле | Значение |
|------|----------|
| **Статус** | ✅ accepted |
| **Дата** | 2026-09-11 |
| **Автор** | kimi-code |

## Контекст

До 2026-09-11 состояние было раздвоено: документы жили в DB cod-doc (144 проекции, drift-check), ADR — и в DB, и как файлы experiments/adr/*.md, а задачи — только в legacy-файле .cod-doc/tasks.yaml (31 запись, 25 done / 6 failed), невидимом для MCP/agent-поверхности (plan=0, task=0 в DB). Автономный демон cod-doc, генерировавший self-check задачи, отключён 2026-09-07. Проверка 2026-09-11: все 144 .md/.rst/.txt на диске == 144 документам в DB, drift=0.

## Решение

1) cod-doc DB — единственный источник истины для документов, ADR, планов и задач zairgrush. 2) legacy tasks.yaml мигрирован в DB (plan scope imported-legacy, LEG-001..LEG-031); YAML больше не пополняется. 3) Новая работа планируется только через plan/task в cod-doc (CLI или MCP). 4) ADR продолжают жить парами: запись в DB + экспорт файла в experiments/adr/. 5) Демон остаётся выключенным; self-check задачи не создаются.

## Альтернативы

A) Оставить YAML-бэклог параллельно DB — отвергнуто: двойная правда, MCP-агенты видят пустой проект. B) Перевести задачи в GitHub Issues — отвергнуто: теряется связь с документами/ADR и drift-контур. C) Реанимировать демона — отвергнуто: порождает self-noise задачи (6 failed из 31).

## Последствия

+ MCP agent-профиль (agent_pick/agent_report) видит реальный бэклог. + drift/routine контур покрывает и задачи. − tasks.yaml остаётся read-only артефактом истории; при возврате к YAML потребуется обратная миграция. Правило: любая новая задача — через cod-doc task create, иначе она не существует.
