# ADR-002: модель исполнителя по умолчанию — K3 (E8, предварительно)

Дата: 2026-08-07. Статус: принято предварительно (пересмотр после BENCH-2).

## Контекст

E8 (06-док, §4) сравнивал модели исполнителя на одном бенче: A — Kimi K3
(флагман, дефолт с v0.6 дизайн-дока), B — `kimi-for-coding` (K2.7 Coding,
дешёвый вариант). Гипотеза: K3 сходится за меньшее число итераций, а на
механических задачах разница исчезает и дешёвая модель выигрывает по цене.

## Данные

Идентичные условия: те же 6 задач (`e8-tasks.json`), изолированный
worktree `stand-e8` на том же red-state коммите, тот же ревьюер и протокол.

| Метрика | K3 | K2.7 Coding |
| --- | --- | --- |
| Задач закрыто | 6/6, все с 1-й итерации | 6/6, все с 1-й итерации |
| Wall-time реализации | 193 с | 232 с (+21 %) |
| Findings ревьюера | 13 (все minor) | 13 (все minor) |
| Стоимость ревью диффов | $2.31 | **$2.98 (+29 %)** |
| Нарушений scope / dispute | 0 / 0 | 0 / 0 |

Стоимость самого исполнения сравнить нельзя: Kimi не отдаёт usage в
stream-json (§6.0), обе модели работали по подписке.

## Решение

Оставить **K3 моделью исполнителя по умолчанию** (как в §3.2 v0.6).
Роутинг «дешёвая модель на механические задачи» **не вводить** — данных в
его пользу нет: на этом классе задач исход идентичен, K2.7 медленнее, а
ревью его диффов дороже, то есть частичная экономия на исполнителе
съедается удорожанием ревьюера.

## Последствия

- (+) Конфигурация не усложняется правилами роутинга без доказанной пользы.
- (−) Вопрос экономии на объёмных механических правках остаётся открытым:
  бенч состоит из тривиальных гринфилд-задач, где обе модели упираются в
  потолок «одна итерация».
- **Пересмотр обязателен после BENCH-2** (brownfield, диффы больше,
  возможны 2–3 итерации): различие в качестве проявляется числом итераций,
  а его на текущем наборе измерить невозможно.
- Побочное наблюдение для §7.4: стоимость ревью зависит от того, *кто*
  писал дифф — это ещё один аргумент считать бюджет ревьюера отдельной,
  плохо предсказуемой статьёй.
