# ADR-004: хелперы работают через нативный Ollama API; ADR-003 пересмотрен

Дата: 2026-08-07. Статус: принято. **Заменяет ADR-003.**

## Контекст

ADR-003 зафиксировал: «модель хелперов обязана быть non-reasoning, потому
что reasoning-модель возвращает пустой ответ, сжигая лимит в размышления».
Вывод был сделан по замерам через OpenAI-совместимый слой `/v1`, который я
взял как данность, не изучив альтернативу. OLLAMA-1 показал, что это была
ошибка атрибуции.

## Что выяснилось

1. Ollama Cloud отдаёт **нативный `/api/*`** по тому же Bearer-ключу.
2. У нативного API есть параметр `think`, которого нет в `/v1`. На `/v1` он
   **молча игнорируется**.
3. Рассуждения включены **по умолчанию**: если модель умеет thinking, а
   `think` не передан, сервер сам ставит `true`.
4. С `think: false` та самая «непригодная» reasoning-модель отвечает за
   0.8 с и 15 токенов вместо 4.9 с и 679 — в 45 раз дешевле по выходу.
5. При `think: true` и коротком лимите **обе** модели (включая gemma4,
   которая тоже thinking-capable) возвращают пустой content.

То есть непригодна была не модель, а комбинация «reasoning-модель +
транспорт без управления thinking».

## Решение

- Хелперы вызывают **`https://ollama.com/api/chat`**, а не `/v1`.
- В каждом запросе **явно** передаётся `"think": false`. Полагаться на
  дефолты модели запрещено — они включают рассуждения.
- Требование «модель обязана быть non-reasoning» из ADR-003 **снимается**:
  пригодна любая модель, у которой thinking управляем. Ограничение
  сохраняется лишь для семейств, где трассу нельзя выключить совсем
  (`gpt-oss:*` — только понижение до `"low"`), — такие модели для хелперов
  не берём.
- Дефолтная модель остаётся `gemma4:31b` (выбор по скорости и качеству, а
  не по отсутствию reasoning).
- Набор `options` фиксируется: `temperature: 0`, `top_k: 1`,
  `repeat_penalty: 1.0`, явный `num_predict`, `seed`. Обоснование и
  замеры — `experiments/helpers/ollama-reference.md`.
- `num_ctx`, `truncate`, `shift` **не передаются**: на облаке игнорируются
  (проверено: `num_ctx=4096` не обрезал промпт в 51k токенов).

## Последствия

- (+) Открыт весь каталог облачных моделей, а не только non-reasoning:
  выбор теперь по качеству и скорости.
- (+) Детерминизм стал настоящим: на `/v1` нам молча навязывали
  `temperature=1.0` и `top_p=1.0`, что противоречило требованию
  воспроизводимости.
- (+) Появились сигналы, которых не было: `done_reason == "length"` —
  честный признак обрезанного ответа; `x-request-id` — для поддержки.
- (−) Нативный API не является отраслевым стандартом: при смене провайдера
  клиент придётся переписывать. Приемлемо — это ~40 строк на stdlib.
- Осталось в силе из ADR-003: **текст хелпера всегда проходит механическую
  проверку**. Более того, требование усилилось: `format` со схемой на
  облаке официально не поддержан и эмпирически игнорируется, поэтому
  структура ответа хелпера — целиком наша ответственность.

## Урок методологии

Вывод, сделанный внутри одного транспорта, был выдан за свойство модели.
Правильная формулировка отрицательного результата требует называть
границы эксперимента: не «reasoning-модели непригодны», а «через `/v1`
reasoning-модели непригодны, потому что thinking неуправляем». ADR-003
сохранён в истории как пример такой ошибки.
