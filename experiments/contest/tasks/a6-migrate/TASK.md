# A6 — SQLite → JSONL migration

Напиши модуль `solution.py` с функцией:

```python
def migrate(db_path: str, out_path: str) -> bool: ...
```

Одноразовая миграция таблицы в JSONL. Требования production-grade: атомарность, идемпотентность, отсутствие мусора при сбое.

## Требования

- Читает таблицу `events(id INTEGER PRIMARY KEY, ts TEXT, payload TEXT)` из SQLite-базы `db_path`, строки упорядочены по `id` ASC.
- Пишет в `out_path` по строке на событие: `{"id": <int>, "ts": <str>, "payload": <str>}` + `\n`. Кодировка UTF-8, `ensure_ascii=False`. Пустая таблица → файл из 0 строк (файл создаётся).
- Возвращает `True`, если файл был (пере)записан; `False`, если `out_path` уже существует и его содержимое побайтово совпадает с тем, что должно получиться (идемпотентный no-op).
- Атомарность: запись через временный файл В ТОМ ЖЕ каталоге + `os.replace`. Ни при каком сценарии не должно быть частично записанного `out_path`.
- Rollback: любая ошибка (нет таблицы `events`, битая база и т.п.) → существующий `out_path` остаётся БЕЗ ИЗМЕНЕНИЙ (или отсутствует, если его не было), временные файлы удалены.
- Отсутствие таблицы `events` → `RuntimeError`.
- Родительский каталог `out_path` существует (создавать не нужно). `db_path` может не существовать — это ошибка, обрабатывается как выше.
