# A1 — TTL LRU cache

Напиши модуль `solution.py` с классом:

```python
class TTLCache:
    def __init__(self, maxsize: int, ttl: float, clock: Callable[[], float] = time.monotonic): ...
```

Кэш ограниченной ёмкости с TTL и вытеснением по LRU.

## Требования

- `maxsize >= 1`, `ttl > 0`, иначе `ValueError`.
- `set(key, value)` — вставить/обновить. Ключи — строки. Обновление существующего ключа обновляет его recency и продлевает TTL (таймер с момента последнего set). Если после вставки размер превышает `maxsize`, вытесняется наименее недавно использованный живой ключ (eviction).
- TTL-граница: ключ, ровно достигший возраста `ttl`, считается ЖИВЫМ; он протухает строго позже `ttl` (т.е. expired ⇔ `clock() > set_time + ttl`).
- `get(key)` — значение или `None`, если ключа нет или он протух. Успешный get обновляет recency. Get протухшего ключа удаляет его.
- `delete(key)` — `True` если живой ключ был и удалён, иначе `False`.
- `__len__` — число ЖИВЫХ ключей (протухшие не считаются).
- `stats()` — `dict` с ключами `hits`, `misses`, `evictions`, `expirations` (int, с нуля):
  - `hits` — get по живому ключу; `misses` — get по отсутствующему или протухшему.
  - `evictions` — вытеснения по LRU при переполнении.
  - `expirations` — обнаруженные протухания (любым методом, один раз на ключ).
- Время берётся ТОЛЬКО из параметра `clock` (по умолчанию `time.monotonic`) — тесты подсовывают fake clock. Прямые вызовы `time.time()`/`monotonic()` внутри класса запрещены.
- Ленивая протуханность: фоновых потоков нет; протухание обнаруживается при обращении к ключу или при подсчёте `__len__`/`stats`.
