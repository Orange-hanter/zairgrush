# A2 — Cron parser + next_fire

Напиши модуль `solution.py` с функцией:

```python
def next_fire(expr: str, after: datetime) -> datetime: ...
```

## Синтаксис (подмножество cron)

Пять полей через пробел: `minute hour day-of-month month day-of-week`.

- Диапазоны: minute `0-59`, hour `0-23`, dom `1-31`, month `1-12`, dow `0-6` (0 = воскресенье; 7 НЕ принимается).
- В каждом поле: `*`, `*/n`, `a`, `a-b`, `a-b/n`, списки через запятую из любых этих элементов (`0,30`, `1-5,10`, `*/15,45`).
- `n` (шаг) >= 1. Всё остальное — `ValueError` (невалидный диапазон, шаг 0, не число, не то число полей, пустая строка).
- Лишние пробелы между полями допустимы (`"  0   9 * * *  "`).

## Семантика

- Возвращает ближайший момент СТРОГО позже `after` (с точностью до минуты: секунды/микросекунды `after` отбрасываются при сравнении, результат имеет `second=0, microsecond=0`).
- Стандартное правило cron для dom/dow: если ОБА поля ограничены (не `*`), день подходит, когда совпадает ХОТЯ БЫ одно; иначе должны совпасть оба.
- Naive datetime, timezone не учитываем, DST не существует.
- Если совпадения нет в ближайшие 4 года от `after` (например `0 0 31 2 *`) — `ValueError`.

## Примеры (для самопроверки)

- `next_fire("0 9 * * *", datetime(2026, 9, 18, 8, 0))` → `2026-09-18 09:00`
- `next_fire("0 9 * * *", datetime(2026, 9, 18, 9, 0))` → `2026-09-19 09:00` (строго позже)
- `next_fire("0 0 29 2 *", datetime(2026, 1, 1))` → `2028-02-29 00:00`
